iWhether this provider's API natively accepts {type: "custom"} tool definitions.

When enabled: custom tools pass through as-is.
When disabled: custom tools are downgraded to function wrappers with a synthesized JSON schema, then restored on the response path.

Only OpenAI's official API supports custom tools natively. Third-party Chat Completions providers (DeepSeek, Moonshot, etc.) typically do not.

OpenAI Function Calling docs →
iRewrite mid-conversation system/developer messages as user-role envelopes ([System: ...]) to preserve the prompt cache prefix.

When enabled: late system messages are hoisted — leading ones move to the system instruction, mid-conversation ones become user messages. This keeps the cacheable prefix stable and avoids silent message loss on some providers.

When disabled: system messages are left in their original positions. This may break prompt caching or cause message loss on providers that reject non-leading system messages.
iSend a cheap non-streaming request (max_tokens=1) before each streaming request to obtain exact input_tokens in the Anthropic-format message_start event.

When enabled: adds one extra API round-trip (~0.5–1s) and bills input tokens twice. Only fires for cross-format streaming (source ≠ target).

When disabled: input_tokens will be 0 in message_start for non-Anthropic upstreams (usage is still reported at stream end).

Can also be toggled per-request via the X-Rosetta-Preflight-Tokens header.
