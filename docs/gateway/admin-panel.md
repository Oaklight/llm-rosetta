# 管理面板（Admin Panel）

网关内置一个 Web 控制台，用来管配置、看流量、做诊断 —— 不用手改配置文件，改完也不用重启。

访问地址：**`http://localhost:8765/admin/`**

## 控制台

控制台左侧是分区导航栏：**Dashboard**、**Providers**、**Models**、**API Keys**、**Observability**。底部一行放模式、语言、设置与登出按钮；最下沿的状态栏常驻显示请求计数。顶部另有一条吸顶状态条，标出当前所在分区：方括号序号加页面标题（`[03] Model Routing`），文字取自该面板自己的标题。内容区铺一层 32px 的细网格。窗口窄于 900 px 时，侧栏折叠为横向条，当前项以下划线标记；顶部状态条保持不动。

侧栏底部是时钟。它显示网关自己的时间，而不是浏览器时间：`/health` 报告进程的时钟与时区，点击时间切换到浏览器时钟（标签会说明当前是哪一种，选择会被记住）。紧邻的时区是第二个点击目标 —— 默认显示 GMT 偏移（`GMT-5`），切换后显示 IANA 名称（`America/Chicago`）；名称比侧栏宽时以省略号截断。直接访问 `/admin` 会打开 Dashboard，而不再恢复上次停留的分区；显式 hash（`#providers`、`#models`）仍然深链。日志分区现在是 `#observability`，旧的 `#logs` 书签仍能打开它，并会被改写为新的 hash。

`Alt+1` … `Alt+5` 直接跳到某个分区，`[` 与 `]` 依次切换，浏览器的前进后退在访问过的分区之间移动，`?` 打开快捷键列表。

## 提供方（Providers）

**Providers** 分区管理网关能调用的全部上游。

![提供方分区](images/admin-providers.png)

顶部按模型类型筛选 —— **All**、**LLM**、**Embeddings**、**Rerank**、**Decisions** —— 并按名称、shim 或 Base URL 搜索；旁边的数字是筛选后剩下的提供方数量。网格 / 列表按钮在卡片和紧凑表格之间切换，选择保存在 `localStorage`。**+ Add Provider** 打开表单；**+ Free resource** 列出网关已知的免费通道，选中一个等同于添加对应提供方。

每张卡片显示 Logo 与名称、该提供方所服务模型类型的能力徽章、启用开关，以及其下的模型数量。禁用的提供方只把 Logo 灰化、名称变淡，卡片仍然可读。操作按钮是 **Edit**、**Test** 与 **⋯** 菜单，菜单里有 **Clone**、**Refresh**（shim 声明了模型列表路径时）、**Quota**（shim 带有探针时）与 **Delete**。

工具条上的**状态**分面 —— **All**、**Needs attention**（需要处理）、**Disabled**（已禁用）—— 按提供方当前的状态筛选，计数随其他筛选后的剩余集合实时变化。列表本身也有顺序：有问题的排在最前，正常的其次，被关闭的排最后，因此停止路由的端点浮在顶部，而不会淹没在网格里。这个顺序在你操作时保持不变：拨动开关不会移动那一行，重新进入本节、切换筛选或修改搜索时才会重新排序 —— 否则刚被关掉的提供方就会在指针下方离开视口。

不参与路由的能力徽章同样灰化；因解析失败而降级的徽章还带一个 `!` 角标，角标的 tooltip 先给翻译后的分类，再附上网关自己的原句，具体是哪个 shim、哪个字段一悬停就能看到。整条提供方失败（未知 shim、缺少 Base URL）会出现在与按类型失败相同的那一行警告里。

端点可以单独关闭：provider 条目上的 `<type>_enabled: false` 只把该提供方从该模型类型的池中移除，配置原样保留。表单里每个端点段各有一个 **Enabled** 开关；LLM 段的开关就是提供方自己的 `enabled` —— 对话就是提供方本身，而不是它的某个端点，所以没有单独的 `<type>_enabled`。新建提供方时四个能力都不勾选：它服务哪些能力是第一个要做的决定；一个都不选就保存会被拒绝，而不会写入一个什么都不服务的提供方。失败的端点开关保持打开，并在单独一行说明原因 —— 若把开关关掉，下一个保存就会把自动故障变成手动关闭，修好 shim 之后它仍然是关的。被自动禁用的提供方，LLM 开关同样是打开状态，修好原因后保存即可恢复，正如状态行所说。

卡片故意不显示类型行和 Base URL：一个提供方可以同时服务多种模型类型，徽章比单个单元格说得更清楚；URL 放在名称的 tooltip 和表单里。

### 添加与编辑

提供方表单从右侧以抽屉形式打开，标题、标签栏与操作区固定。表单分为两页：**基础** 放身份、传输与路由，**认证** 放凭据。抽屉每次都先打开 **基础**；**认证** 标签上的红点表示凭据需要处理 —— 尚未登录、连续失败、记录不可读，或条目里留着旧标记。切换标签不会重跑类型选择器，端点选择不会在操作者脚下改变。

- **基础** —— Logo、名称、只读的模型类型摘要、Base URL、模型列表路径、代理与超时、只读的凭据摘要（实际来源、状态胶囊与说明，以及 **在“认证”中更改**）、模型类型复选框和端点卡片。LLM 端点卡片保留类型选择器、URL 模板、工具开关与工具描述最大长度。
- **认证** —— 凭据来源卡片、密钥输入框、命令编辑器、登录记录面板、刷新日志，以及保存将写入字段的预览。

- **重命名** 会自动改写所有引用该提供方的模型。
- **克隆** 会把源提供方的设置预填进抽屉，名称预填为 `<name> Clone`（中文界面为 `<name> 克隆`）。
- **删除** 会弹出输入确认框，并提示级联影响：该提供方下的模型会一并删除。

API Key 字段自动识别逗号分隔的多个密钥，并切换为多条目列表 —— 每个密钥一行密码输入框。**+ Add key** 随时追加一行；每行有显示 / 隐藏切换与复制按钮，底部提供整段逗号分隔值的“查看全部”和“复制全部”。卡片上显示的脱敏 Key 不会被写回配置文件。两页都是静态 DOM：切换标签、语言或提供方都不会重建密钥行或已粘贴的记录。

### 凭据来源

**认证** 页按加载器的优先级打开实际生效的来源：条目里的 `token_command` 优先，其次是 Shim 的命令、Shim 的 `auth.py`，最后是静态 Key。四张卡片代表四种来源，只显示加载器能接受的选项：

| 来源 | 何时提供 | 保存的字段 |
|------|----------|------------|
| 静态 API Key | Shim 不生成凭据（无密钥的 Shim 仍有此卡，可自带付费 Key） | `api_key` |
| 配置文件中的命令 | 始终提供 | `token_command`、`token_command_env`、`token_refresh_interval` |
| Shim 自带的命令 | Shim 声明了 `connection.token_command` | 仅 `token_refresh_interval`；argv 只读 |
| 登录（`auth.py`） | Shim 带有交换，或条目已经使用交换 | 交换自己维护的记录 |

选择一种来源就是对其他来源的表态：选择 Shim 命令、登录或静态 Key 会清空条目的 `token_command`；离开静态 Key 会发送 `clear_api_key`，旧密钥被删除而不是保留。卡片下方的预览写明保存将写入什么 —— Key 只显示 `<set>`、`<kept>` 或 `<cleared>`，从不显示值或前缀。

命令编辑器按 argv 行编辑：一行一个参数，第一行是可执行文件。命令至少保留一个参数 —— 最后一行不显示 ×，要移除命令请改选其他凭据来源。`token_refresh_interval` 至少 60 秒。命令通过 `token_command_env` 接收操作者密钥时，密钥输入框保留 —— 那里密钥是命令的输入，不是第二个凭据。声明了 `consumes_key` 的交换同样保留该输入框。

状态卡显示实时的 `token_status`：上次取 token、连续失败次数、最近错误、是否需要交互登录，以及首个 token 尚未返回时的 `initializing`。页面只显示指纹（命令为 `cmd:<sha256>`，密钥为 `key:<sha256>`）与时间，不显示 token 本身。

**立即刷新**（`POST …/credential/refresh`）会跳过定时周期重新取 token —— 上游 401 路径会对突发去抖，这个按钮不会。**测试凭据**（`POST …/credential/test`）会取一次 token 并用它请求提供方的模型列表端点；返回值说明上游是否接受该凭据，因此不会把“命令退出码为 0”误当成“账号可用”。两个按钮运行的都是**已保存**的命令：草稿与已保存状态不一致时它们会禁用并说明原因，而不是去测一份还没保存的配置。

对于 Shim 的 `auth.py` 交换，同一页承载记录操作；只有交换报告 `can_install` / `can_revoke` 时才显示，不会提供必然返回 501 的按钮：

| 状态 | 面板显示 |
|------|----------|
| 已连接 | 交换摘要给出的账号、访问令牌到期时间、**管理用量**（shim 声明了页面时）与 **退出登录** |
| 需要登录 | 尚无凭据 —— **安装记录**；此时仍可保存提供方，好让 CLI 有对象可登录 |
| 无法读取 | 记录存在但读不出来 —— 可安装新记录或退出登录 |

**安装记录** 接收 CLI 打印的 JSON（`llm-rosetta-gateway credential <provider>`，见 [CLI 参考](cli.md#credential-provider)），经 `PUT …/credential` 交给交换；校验不通过的记录会带着交换自己的说明被拒绝。**退出登录** 调用 `DELETE`：厂商允许时会在上游撤销授权，并立刻把令牌从网关的 key ring 中移除。

Key 槽里存着字面量 `token_command` 的条目（旧编辑器写下的标签）会在认证页给出提示；下次保存会删除该字面量 —— 与命令并存时加载器会拒绝这一对。

保存或启用提供方前，会先在内存中构建相关提供方。加载器拒绝的文档返回 400 且不写配置文件，不再先落盘再返回“Config saved but reload failed”。

## 模型（Models）

**Models** 分区就是模型路由表：每个已配置的模型、它声明的能力，以及为它提供服务的提供方。

![模型分区](images/admin-models.png)

- **筛选** —— 提供方与状态分面（**All statuses**、**Usable**、**Partial**、**Unusable**，计数按其他筛选后的结果重算）占第一行；模型类型单独占第二行，与日志页的分面排法一致，窄屏时不会在组内折行。
- **徽章**只有图标，能力名称是 tooltip。由多个提供方服务的模型显示 **Multiple providers**，点击单元格展开列表，每个提供方各有开关、权重、能力选择器与 **Test**。选择器用同色的小圆点显示该条目的能力；点击后展开 `text`、`vision`、`tools`、`reasoning` 的勾选清单，空心圆点表示该条目继承提供方自身的能力。被关闭的提供方保留原位。
- **操作** —— 鼠标悬停到行上才出现 **Test** 与 **⋯**；启用开关始终显示，它就是这一行的状态。
- **点击行打开侧面板** —— 能力、每个提供方及其权重与同一个能力选择器、**Edit** 都在同一个面板里，不再有独立的模型弹窗。
- **提供方顺序** —— 由多个提供方服务的模型，按选择器尝试的顺序列出它们。表格里的 **Multiple providers** 下拉与侧面板中的行都可以抓住手柄拖动；松手后写入模型的 `providers` 列表。被关闭的提供方保留原位。
- **排序** —— 表格滚动时表头固定；没有任何提供方能服务的模型排在可用行之后。

![按提供方选择能力](images/admin-model-capabilities.png)

不在表内的操作有两个：标题栏的 **+ Add Model**，以及 **Fetch from Provider** —— 它查询上游 `/v1/models`，带复选框列出返回结果，按可选前缀批量添加。失败信息是可操作的诊断结论，而不是笼统报错：

- **连接被拒绝** —— 上游服务未运行，或防火墙拦截了连接
- **超时** —— 从网关无法访问上游主机
- **DNS 解析失败** —— Base URL 的主机名解析不出来

把模型重命名为已存在的名称时会合并提供方，而不是失败：确认框会把新提供方加入 `providers[]`，而不是覆盖原本持有该名称的条目。只有确实能加入车道时才会提示合并。同一提供方可以服务多个上游模型，因此把该提供方以不同的 `upstream_model` 合并进来会追加一条车道，而不是被拒绝；只有完全相同的 `(provider, upstream_model)` 对出现两次才以 `409` 拒绝，两个模型保持原样 —— 面板给出的原因会列出目标已在使用的车道。

### 模型能力

每个模型可声明能力，决定可用的测试类型，并在 `/v1/models` 响应中返回：

| 能力 | 说明 | 徽章颜色 |
|------|------|---------|
| `text` | 文本生成 | 灰色 |
| `vision` | 图像理解 | 品红色 |
| `tools` | 函数/工具调用 | 青蓝色 |
| `embedding` | 文本嵌入（与 vision/tools 互斥） | 蓝色 |
| `reasoning` | 扩展思考/思维链（与 embedding 互斥） | 柠檬绿 |

这些色相避开了状态用色 —— 红色、绿色、橙色在面板其他地方已分别表示失败、正常、警告 —— 只留一个例外：reasoning 用柠檬绿，色相偏向黄色，不会被误认成路由面板上表示正常的绿点。

### 模型测试

点击模型行上的 **Test** 运行快速测试；可选的测试类型取决于声明的能力：

| 测试类型 | 说明 | 需要能力 |
|---------|------|---------|
| Text | 简单文本查询 | `text` |
| Vision | 图像理解（内嵌测试图片） | `vision` |
| Stream | 流式文本响应 | `text` |
| Tools | 函数调用（天气工具） | `tools` |
| Embedding | POST 到 `/v1/embeddings`，显示维度数量 | `embedding` |
| Reasoning | 文本查询，附带 `reasoning_effort: "low"` | `reasoning` |

Embedding 模型只显示单一的 Test 按钮，因为只有一种测试适用。

由多个提供方服务的模型，按你在其提供方列表里选中的那个来测，通过 `X-Rosetta-Provider-Pin` 头固定 —— 网关只对管理面板内部令牌认可该头。测试进行中可以 **Cancel** 中止，状态旁有实时计时器。测试负载使用 `max_tokens=256`。结果主区域显示提取出的回复，可折叠区域包含原始请求、原始响应体，以及视觉测试的图片预览。

### 删除确认

破坏性操作按严重程度使用两种确认方式：

- **删除提供方** —— 弹出输入确认框，并说明级联影响。
- **删除模型**、**删除 API Key** 与 **Clear Log** —— 内联两步确认：按钮变为 **Sure? Yes**，3 秒内未确认则自动恢复。

## 路由（Routing） { #routing }

**路由** 区按模型回答一个问题：哪条通道在服务它，为什么。它读取选择器自己的答案，而不是在浏览器里再算一次 —— 页面上的每个数字都来自 `GET /admin/api/routing/<model>`。

![路由区](images/admin-routing.png)

- **列表（Board）** —— 按选择器读取的顺序展示路由：每个候选的序号、通道及其背后的线格式与 shim、可直接改写模型条目的权重加减器、剩余额度、它实际服务的份额，以及带倒计时的状态。拖动行首的把手即可改顺序；松手后写入模型的 `providers` 列表，因此列表显示的顺序就是选择器读取的顺序。每行还带一个开关，写入提供方自己的条目，不用离开本页就能把一条通道摘下或放回。提供方被关闭的通道仍留在列表里：它排在候选之后，状态为 **已关闭**，副行写出原因；它的开关可用，权重、拖动与份额都不起作用 —— 从页面上消失的通道，没有人会注意到它挂了。拨动开关后该行留在原处；下次进入本页或切换模型时才重新排序。
- **图例** —— 说明三个圆点（**可用**、**沉底**、**因拒绝被封锁**）和该模型份额的算法：`weighted` 为权重 × (0.25 + 0.75 × 余量)，`ordered` 归第一个可用通道，`rotate` 与 `least_used` 均分，`pace` 只看剩余额度。
- **决策（Decisions）** —— 来自请求日志的该模型最近请求：时间、请求 id、客户端、所选通道、切换记录、状态码与耗时。客户端一格显示 API key 的标签，下面一行是这次请求带的 `User-Agent`，因此一行记录说明的是发出请求的程序，而不仅是它用的 key。 点击一行会在下方展开链路 —— 谁发起、由哪条通道服务、原因是什么 —— 再点一次收起。
- **会话（Sessions）** —— 该模型最近日志中的每个对话一行：key 标签与其 `User-Agent`、最后落到的那条通道、请求次数与时间。网关用客户端 key 与请求的首条消息推导会话 id，只在请求日志里保留摘要，因此同一个 key、同一个 `User-Agent` 下的并发会话各自成行。没有 id 的行——列出现之前写入的历史行，或没有可推导依据的请求——回退到客户端身份，并标注 **客户端分组**。表上方一行给出所取请求中的会话数，并说明客户端与首条消息相同的两个会话计为一个；同一行也说明该模型是否开启亲和。
- **策略（Policy）** —— 打开时所在的分页：路由列表、图例，以及它们下方卡片里的 `routing` 块：五个预设以标签形式排列（**均衡**、**会话粘性**、**优先靠前**、**轮转分摊**、**配额节约**），加上策略与亲和、沉底开关、首字超时、按原文列出的规则，以及块的 JSON 预览。预设写入的是运维本可以手写的字面块；不属于任何预设的块，所有标签都不高亮。

剩余额度一格报告该通道最接近耗尽的窗口，并在副行写出窗口名（例如 `余量 0.00 · Month`）。点击该格会在通道上报的窗口之间轮换，悬停则列出每个窗口的剩余百分比与重置时间。没有配额探针的提供方显示 **无探针**，有探针但尚无读数时显示 **未测量**；两种情况下通道都按配置权重参与分配，因为份额公式把未测量的余量当作无惩罚。

状态直接来自资格判定，所以面板与代理的结论在结构上一致：

| 状态 | 含义 |
|------|------|
| **服务中** | 候选，没有被挡住 |
| **沉底** | 仍是候选，但最近的 429 让它排在最后 |
| **已阻塞** | 提供方级阻塞（无 key 通道的 429、账户额度耗尽的轮换凭证）；该行倒计时到结束时间，到期后自动刷新 |
| **限流中** | 连续 429 让该通道退出轮换，直到冷却结束 —— 或连续容量类拒绝（`503`、`529`、`520`-`524`）禁用了那条上游车道，其同级车道仍在轮换中 |
| **配额耗尽** | 每个凭证的最新读数都显示窗口已耗尽 |
| **无凭证** | 密钥环里没有可用凭证 |
| **启动中** | 凭证尚未装载 |
| **已关闭** | 提供方在「提供方」页被关闭，路由因此不包含该通道；该行仍排在候选之后，除开关外只读 |

左侧的模型列表就是选择器：每个可路由模型一行，按最近一次被请求的时刻排序，显示该窗口的请求数、提供方数量、这些提供方的份额，以及被阻塞的通道数。被阶梯挡下的车道与提供方级阻塞分开报告：路由行上方的徽章给出被限流的车道数与其中最晚的恢复时间，每条车道的提示只给出这条车道自己的状态、以及被阶梯挡下时它自己的结束时间 —— 因为阶梯属于单条车道，而提供方自身的 `block` 仍然只表示凭据级（`429`）事实。打开页面时默认选中第一行 —— 也就是最近一次被请求的模型；再次进入时保留屏幕上的模型。上方的搜索框随输入收窄列表。窗口切换（**5h**、**24h**、**7d**、**全部**）重新统计并重排列表；默认 5 小时，因为这一页回答的是「现在正被路由的是什么」。数据来自 `GET /admin/api/routing?window=…`，也就是运行时的路由表而不是配置文档里的全部键，因此加载时被跳过的提供方不会出现。

保存策略通过 `PUT /admin/api/routing/<model>` 写入，该请求会重建配置 —— 因此解析器拒绝的值会以解析器自己的消息返回；编辑器不负责的键（`rules`、`first_token_ms`）在保存时原样保留。

## API Keys

**API Keys** 分区签发和吊销调用 `/v1/*` 的密钥。每个密钥有标签、允许的 shim 列表（`*` 表示不限）、创建时间与最近使用时间。新建密钥时完整显示一次，列表里只保留 id 与标签。删除密钥在下一个请求生效，无需重启。

## 可观测性（Observability）

**Observability** 是一个面板，用五个视角看同一批流量。

![可观测性 —— 请求](images/admin-observability.png)

| 视角 | 内容 |
|------|------|
| **Requests** | 每个代理调用一行 —— 请求日志 |
| **Ops Log** | 服务端事件：生命周期、配置、密钥、数据变更、安全、健康 |
| **Error Dumps** | 失败请求背后的报文 |
| **Profiling** | 阶段性能分析的开关 |
| **Capture** | 请求 / 响应抓取的开关 |

### 筛选

五个视角共用一套筛选词：

- **Time** —— All time、Last 1h、Last 24h、Last 7d、Last 30d，或自定义区间
- **Status** —— All、OK (2xx/3xx)、4xx、5xx，或自定义状态码
- **Provider**、**Model**、**API Key** —— 与配置里定义的列表一致

### 请求行

| 列 | 说明 |
|----|------|
| Time | 请求时间戳 |
| Model | 请求中的模型名称 |
| Source → Target | 来源格式与目标提供方 |
| Mode | 流式请求显示 `stream`，非流式留空 |
| API Key | 发起调用的密钥标签 |
| Client IP | 对端地址 |
| Status | HTTP 状态码（颜色标记） |
| Tokens | prompt 与 completion 计数，提供方上报时含 cache read |
| Duration | 端到端耗时；已知 token 用量时附带每秒输出 token 数 |

流式请求的耗时是流式正文的时间跨度，而不是收到响应头的时间，因此旁边的速率反映的是客户端真正等待的时长。

**Pause refresh** 冻结列表便于细看。**Clear Log** 在内联确认后清空当前视图。

### 错误转储

错误转储在 `#dump/<id>` 全屏打开 —— 与其他页面一样位于登录门禁之后 —— 每一节都有复制与下载按钮，批量选择（**select all**、**invert**）作用于筛选后的结果而不是当前页。标题框显示筛选后剩下的行数。

### 服务端运维日志

运维日志以结构化元数据记录变更与安全事件。

#### 事件类别

| 类别 | 事件类型 | 描述 |
|------|----------|------|
| 生命周期 | `startup`、`shutdown` | 服务器启动和优雅停止 |
| 配置 | `config_reload`、`admin_setup` | 配置热重载、管理面板初始化 |
| API Key | `key_create`、`key_update`、`key_delete`、`key_rotate` | 密钥管理操作 |
| 数据变更 | `data_cleared`、`data_cleanup`、`data_trimmed`、`data_vacuumed`、`data_rebuilt` | 数据库维护操作 |
| 安全 | `password_changed`、`token_rotated`、`session_logout_all` | 认证和会话事件 |
| 健康 | `health_status_change` | 提供方健康状态变化 |

#### 严重性级别

- **info** —— 非破坏性操作（密钥创建、配置重载、vacuum）
- **warning** —— 破坏性数据变更（清除、裁剪、清理）和安全事件（密码更改、令牌轮换）

操作失败时自动以更高严重性记录。

#### 来源过滤

| 来源 | 操作 |
|------|------|
| `admin` | 管理面板操作（清除数据、会话注销） |
| `auth` | 密码更改、令牌轮换 |
| `keys` | API 密钥创建/更新/删除/轮换 |
| `persistence` | 后台修剪、定期清理 |
| `gateway` | 启动、关闭 |
| `config` | 配置重载 |

#### ops_log 与 request_log 对比

**请求日志**记录每个代理请求（高频，流量导向）。**运维日志**记录变更和安全事件（低频，审计导向）。两者独立查询，自动刷新跟随当前视角。

### 日志保留

保留策略在 **Settings → Logging & data** 中配置，按存储分别生效 —— 请求日志、错误转储与运维日志各有自己的上限与保留天数：

- **基于数量**：保留的最大条目数（超出时淘汰最旧的）
- **基于时间**：超过阈值时间的条目自动清理

两个阈值独立生效 —— 先触发的那个优先。

## 设置（Settings）

**Settings** 是整页控制台，左侧有子导航，而不是一叠卡片。每行一项设置，控件按内容宽度排布，不横跨整页。服务端范围内的分组改动即保存；涉及数据库的分组保留显式的 **Save**。

![设置 —— 安全](images/admin-settings-security.png)

| 分栏 | 内容 |
|------|------|
| **Appearance** | 配色方案、模式、语言、模型类型名称、自动刷新间隔与主题覆盖 |
| **Behavior** | 控制台输出级别、错误详情、凭据明文显示、全局代理 URL |
| **Rate limiting** | 开关、算法（滑动窗口、令牌桶、固定窗口、GCRA）与作用范围（全局、按 IP、按密钥、按模型） |
| **Logging & data** | 请求日志上限与保留天数、错误转储上限、导出与清理、运维日志保留 |
| **Security** | 管理令牌及其轮换、**Logout All**、密码表单与会话有效期 |
| **Shims** | 声明的源与已加载 shim 清单 |
| **About** | 配置文件路径、版本与链接 |

**全局代理 URL** 放在这里而不是提供方页：它是服务端级设置，对所有未单独覆盖的提供方生效。

### 主题覆盖

**Appearance → Theme override** 在内置方案与下游片段之后追加 CSS。它保存到 `server.admin_custom_css`，保存即生效，之后每次加载页面也生效 —— 运维可以在控制台里改外观，不必从代码里下发 `custom_head`。要改主题 token 的规则需要使用对应方案自己的选择器。

### 会话有效期

**Security → Sessions** 用两个答案描述会话，同一个会话只会适用其中一个：

- **Sign out after inactivity** —— 会话在每个已认证请求上滑动的窗口（`server.admin_session.idle_minutes`，默认 30，`0` 表示永不过期）。面板自己的空闲计时器读的是同一个数。
- **Stay signed in for** —— "保持登录"会话拿到的持久 cookie 有效期（`server.admin_session.remember_days`，默认 30，`0` 表示登录页不提供该选项）。被记住的会话忽略空闲窗口，只在自己的有效期结束时终止。

两者都在下一个请求生效；登录前 `/admin/api/auth-check` 就会返回这两个值，登录卡片据此说明当前适用哪一条。

### Shim 源 { #shim-sources }

**Shims** 分栏声明外部源，并列出实际加载了什么。

![设置 —— Shim](images/admin-shims.png)

**声明的源** —— 顶层 `shims` 配置段（见 [外部 Shim 源](configuration.md#external-shim-sources)）：**Directories**（每行一个）、**Preload presets**（包的下拉选择）、**Remotes**（JSON 数组），以及其余开关 —— 缓存目录、重新拉取间隔、源加载失败时拒绝启动。**Save** 保存该段并重新应用，因此在这里移除的源无需重启即停止加载；**Refetch** 强制重新下载所有远程源（绕过缓存与 `refresh` 设置）；**Check now** 重新读取每个远程源在 GitHub 上的提交并刷新更新标记。失败的源会在这里报告，但不会阻止网关启动。

**预加载预设。** 下拉框列出网关已知的全部独立 shim 包，每行是名称与 shim 数量，悬停显示仓库地址；免费资源排在付费包之前。点击一行即切换它在 `shims.presets` 中的键；按下 **Save** 之前不会写入，因此选择器旁有一行操作说明，按钮旁会显示 *有未保存的更改*。每个键由服务端展开；URL 相同时，显式 remote 覆盖对应的预设；catalog 不认识的键没有对应行，但会保留在声明中，并由触发器显示其名称。参见[独立 Shim 包](../guide/shims.md#standalone-shim-packages)。

**已加载的 shim。** 源列表下方列出每个已注册的 shim，按其来源分组 —— 组标题带来源的状态、解析出的 ref、数量、失败信息，以及更新结论：*已是最新*、*可更新 `<旧>` → `<新>`*（点击即重新拉取全部远程源）或 *检查失败*（悬停看 API 错误）。该结论比较的是源拉取时的提交与它声明的 ref（未声明 `ref` 时用默认分支）现在指向的提交；结果缓存五分钟。声明为本地目录的 shim 可以在这里打开、编辑和删除；改动后加载失败的编辑会回滚到上一版文件，仍有提供方引用该 shim 时删除会被拒绝。也可以把 shim **禁用**再用 `shims.disabled` 重新启用 —— 那是声明而不是删除，所以同一份定义还能回来。内置与远程 shim 在这里只读，行上会说明原因；直接放在声明源根目录的定义同样只读，因为加载器不读它，而删除"它所在的目录"会带走整个源。

**提供方清单。** 没有身份字段的 `<vendor>/provider.yaml` 是提供方清单：它声明其下每个 shim 逐字段继承的连接默认值。清单在清单页里是独立一行，标为 `manifest`，位于它供给的那些 shim 之上。打开后，文件旁边是继承面板 —— 每个字段一行，`headers` 因按键合并而每个 header 一行 —— 写明哪些 shim 继承该字段、哪些覆盖了它。编辑文本时，面板会对每个叶子重新执行一次合并，标出本次编辑触及的字段，并统计取值会改变的 shim 数量，因此改动 `base_url` 会显示它波及每个没有自行声明该字段的 shim。保存会写入文件、重新加载 shim 源，并列出取值发生变化的 shim。编辑按 provider schema 的清单形状校验，文件中出现 `name` 会被拒绝，而不会变成一个 shim；来自内置或远程源的清单只读，原因与该处 shim 相同。清单不是 shim：它没有名称，也永远不会出现在提供方选择器里。

**移除提示。** 清单下方提示会列出配置中 shim 即将退场的每个提供方、移除它的版本，以及替代它的源 —— 并提供 **添加替代源** 操作，把替代源追加到 remotes 列表。该列表按请求从配置和加载报告推导得出，无需重启即是最新的。

!!! warning
    声明的 shim 目录或归档会在加载时执行第三方 Python（`transforms.py`）。只添加你信任的
    源，并尽量固定 tag 或 commit SHA。

## 主题

管理面板提供两种配色方案：**Minimal** 与 **Emerald**，各有浅色与深色模式。侧栏的模式按钮在浅色 / 深色 / 跟随系统之间循环，**Settings → Appearance** 里有同样的下拉选择。选择按浏览器配置保存在 `localStorage`（`llm-rosetta-scheme` 与 `llm-rosetta-mode`），并在首次绘制前应用，因此已保存的方案不会先闪一下默认方案。登录卡片上也有同样的模式与语言按钮 —— 这两项都保存在 `localStorage`，登录页语言不对就成了一处死胡同。

配色方案只声明 token 值，由组件决定这些值落在哪里。如果要新增方案，见[管理面板主题](../contributing/admin-themes.md)：契约由 `make test-js` 强制执行，`make theme-matrix` 会对真实运行的面板渲染每个方案 × 模式 × 宽度并保存截图。

## 认证 { #authentication }

管理面板**不需要**网关 API Key。

在配置文件中设置 `server.admin_password` 可启用内置密码保护：

```jsonc
{ "server": { "admin_password": "${ADMIN_PASSWORD}" } }
```

详见[配置 — 管理面板安全](configuration.md#admin-panel-security)。

启用密码保护后，控制台显示登录卡片：产品标识、一个带显示按钮的密码框、大写锁定提示，以及提交后会进入忙碌状态的按钮。**Stay signed in** 复选框只在网关提供该能力时出现，并沿用上次的选择。服务端返回的提示原样显示，因此锁定会写明剩余秒数，而不是笼统的 "Invalid password"。

![登录卡片](images/admin-login.png)

!!! info "无内容闪现"
    浏览器在验证会话期间，管理界面保持隐藏（`body.auth-pending`），认证确认后才显示。这避免了登录卡片出现前界面短暂闪现。

- 认证使用 **HttpOnly + SameSite=Lax** 会话 cookie，`Path=/admin` —— 不会把令牌暴露给 JavaScript。
- 不勾选 **Stay signed in** 时，cookie 随浏览器关闭而失效，会话在空闲窗口（默认 30 分钟无操作；鼠标移动、键盘输入、滚动和点击都算操作）后结束。
- 勾选后，cookie 带上被记住有效期的 `Max-Age`（默认 30 天），会话完全忽略空闲窗口 —— "保持登录"与"空闲超时"是两个承诺，同一个会话只适用其中一个。
- 侧栏底部有 **Logout** 按钮。修改密码时，替换会话会沿用用户此前选择的有效期，因此"保持登录"会延续。
- 会话保存在内存中：网关重启会结束所有会话，无论是否被记住。
- 编程式 API 访问仍可使用 `X-Admin-Token` 头作为回退。

也可以通过反向代理保护管理面板：

- **Caddy**：使用 `basicauth` 指令
- **Nginx**：使用 `auth_basic` 指令
- **Traefik**：使用 BasicAuth 中间件

网关 API Key（在 **API Keys** 分区管理）保护 AI 请求端点（`/v1/*`）。详见[配置 — 网关 API Key](configuration.md#gateway-api-keys)。

## 更新 { #updates }

控制台可以提示有新版本、展示更新内容，并在面板内直接安装。

**气泡。** 网关每六小时向包索引查询一次最新版本（`server.update_check`）；当最新版本高于正在运行的版本时，右上角出现一个小气泡 —— `可更新到 v0.15.0`。点击展开详情：当前运行的版本、可用版本、指向 Read the Docs 完整更新日志的链接（跟随界面语言），以及 **立即更新**。

**更新。** **立即更新** 会为该版本已发布的分发执行 `pip install --upgrade`，然后用同一命令行替换进程镜像。PID 保持不变，因此 systemd unit 或容器重启策略并不是网关恢复的原因。面板轮询 `/health`，新版本应答后自动刷新页面；如果安装失败，旧版本继续服务，并显示 pip 给出的原因。

有两种情况会被拒绝，原因显示在气泡里：

- **可编辑安装**（源码目录）—— pip 会用索引上的发行版替换工作树里的包；
- 环境里没有 `pip`，或配置文件里 `server.self_update: false`。

在容器里，安装结果保留到容器被重建为止；重建新镜像才是长期做法。

**更新日志对话框。** 更新之后第一次加载面板时，会打开新版本的更新说明，内容来自打进 wheel 的更新日志文件。**关闭** 只是关掉对话框 —— 下次加载还会出现；**不再提示** 会把该版本记进 `localStorage`，之后不再出现。没有该文件的构建（从未运行过 `scripts/dev/sync_changelog.py` 的源码目录）不会弹出对话框。

## 国际化

控制台支持 English 与中文。语言按钮在侧栏底部，登录卡片上也有一个。每一处界面文案 —— 包括 tooltip、placeholder、aria-label 与 toast —— 都走翻译层；选择保存在 `localStorage`。

模型类型名称是例外，它有自己的开关：面板在所有位置 —— 徽章、警告行、分面、类型单选与模型行 —— 都按 API 的拼法写作 `llm`、`embeddings`、`rerank`、`decisions`，hover 里给出中文。**Settings → Appearance → Model type names** 把两者对调，希望屏幕上的词跟随语言的运维可以切到中文，此时 hover 里给出英文。默认是英文。About 面板里的 **Docs** 链接同样跟随界面语言：中文模式打开 Read the Docs 的 `/zh-cn/latest/`，而不是站根节点的英文跳转。

!!! note "中文翻译更新"
    "provider"的中文译名已由**服务商**更新为**服务方**，更贴合本地惯用表达。

## 数据持久化

指标和请求日志数据持久化到配置文件旁的单个 SQLite 数据库中：

```
~/.config/llm-rosetta-gateway/
    config.jsonc
    data/
        gateway.db    # SQLite 数据库 — 请求日志 + 指标（WAL 模式）
```

### 工作原理

- **请求日志**条目在每次请求时直接写入 `gateway.db`
- **指标计数器**在每次更新后保存到 `gateway.db`
- **启动时**加载持久化数据——指标和日志在重启后恢复
- **WAL 模式**确保写入崩溃安全，同时不阻塞读取

### 数据保留

最多保留 **5,000** 条请求日志。超出上限时，最旧的条目会自动删除。

### 历史数据迁移

首次启动时，如果数据目录中存在旧版的 `request_log.jsonl` 或 `metrics.json` 文件，会自动导入 `gateway.db` 并重命名为 `*.migrated`。

## 从 Docker 访问宿主机服务

当网关在 Docker 容器中运行，且需要访问宿主机上的服务（例如运行在 `localhost:44501` 的另一个 API 代理）时，不能使用 `127.0.0.1` 作为 Base URL——该地址在容器内指向的是容器自身。

应使用仪表盘网络诊断中显示的 **Host IP**。这是 Docker 桥接网络的网关地址（通常为 `172.x.0.1`），由容器的默认路由自动检测。管理面板中的提供方代理 URL 占位符会动态显示检测到的 Host IP，可直接复制使用。

### 防火墙配置（ufw）

如果宿主机运行了 `ufw`，即使容器和宿主机共享桥接网络，Docker 容器的流量默认也会被阻止。需要显式允许 Docker 子网。

推荐的做法是用一条规则放行整个 Docker 私有地址段（`172.16.0.0/12`）。这涵盖了所有 Docker 网络——默认 bridge、compose 创建的网络，以及未来新建的任何网络——无需逐个网络添加规则：

```bash
sudo ufw allow from 172.16.0.0/12 comment 'Docker all subnets'
```

这是安全的，因为 `172.16.0.0/12` 是 [RFC 1918](https://datatracker.ietf.org/doc/html/rfc1918) 私有地址段，不会在公网上路由。只有运行在同一宿主机上的容器才能使用这些地址。

!!! warning "为什么按网络添加规则不可靠"
    Docker 动态分配子网。如果只放行某个特定的 `/16`（如 `172.29.0.0/16`），用 `docker run` 而非 `docker compose` 启动的容器可能会分配到不同的子网（如 `172.17.0.0/16`），从而无法访问宿主机服务。使用 `/12` 规则可以彻底避免这个问题。

如果防火墙阻止了流量，"从提供方获取"和模型测试会显示超时错误。检查网络诊断中的 Host IP 并添加相应的 ufw 规则即可解决。

## 缓存 / 反向代理

管理面板在所有 `/admin/api/*` 响应上设置 `Cache-Control: no-cache, no-store, must-revalidate`。这可以防止激进的反向代理缓存（例如 Caddy 搭配 Souin 插件）返回过期的仪表盘指标或请求日志数据。

模型测试轮询使用 POST 请求而非 GET，以避免被中间代理缓存。

## 移动端 / 响应式

控制台支持响应式布局 —— 窄于 900 px 时侧栏变成顶栏，设置子导航折叠成内容上方的一条横条，数据表格可水平滚动，不裁切列内容。
