01core 现状:组件与依赖

实线是模块顶层导入,虚线是函数内的懒加载。

说明(12 条)
  • 另一条路径已经隐含的实线导入没有画(传递性约简),带标签和带颜色的线一律保留;完整的边用 python gen_core.py --full 生成。
  • ir、pipeline、formats、auto_detect、contracts 都不导入 shims 与 extensions,shim 名字经 contracts/resolver.py 读取。
  • 四个编排器(chat、embeddings、rerank、decisions)都在 pipeline/,converters 不导入 pipeline,ConversionError 只定义在 converters/base/errors.py。
  • IR 是一个包 llm_rosetta.ir:ir/model(数据,只依赖标准库)在底层,ir/primitives、ir/tools、ir/passes 在它之上;types/ 只放提供方参考形状。
  • shims 向 extensions 注册 shims 处理器(绿线),两者不互相导入。
  • 红色的依赖只有一条:contracts/transform.py 导入 ir.primitives(边表由 tests/test_core_layering.py 固定)。
  • “转换库”组是三层:pipeline 在最上,converters 在中间,IR 在最下,自上而下依赖;没有 shim 时这一组就是完整的转换库。
  • shims 和 extensions 是它外面的可选层;contracts 在共享基础层,被转换、shim、扩展、cli、devtools 共用;api 是宿主门面,core 内部不导入它(有测试保证)。
  • api 只是把下面各包再导出一遍,这些再导出的边不画,免得遮住真正的依赖。
  • tool_ops(入口便捷层)只画到 converters 的边,它到 ir 和 retired_names 的边在 CORE_EDGES 里有,图里不画。
  • 未画的:shims/providers 转发层、弃用的 gateway/ 与 observability/ 转发包。
  • 画的是 master 的树。
