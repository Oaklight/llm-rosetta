# llm-rosetta architecture diagrams

Living architecture diagrams of core and the gateway, kept on their own branch (`docs_arch`) beside the code. Open `architecture.html` in a browser: three mermaid diagrams, scrollable and zoomable.

| Diagram | Source | What it shows |
|---|---|---|
| core, current | `core.mmd` (generated by `gen_core.py`) | core's packages and their imports on `master`; red edges are dependencies that point the wrong way |
| gateway backend | `gateway.mmd` (generated by `gen_gateway.py`) | the layers of `llm_rosetta_gateway`, the data plane and the boundary to core; every package edge is a row of `GATEWAY_EDGES` in `tests/gateway/test_layers.py`, so the picture matches the test (`python gen_gateway.py --check`). Nodes live in `gateway.base.mmd`, edge labels in `gateway.labels.json`, edges to core, client and upstream in `gateway.extra.mmd` |
| gateway admin | `admin.mmd` | the admin pages, their scripts and components, the `/admin/api` groups and the backend they reach |

## Build and check

```bash
python build.py                 # writes architecture.html (mermaid from jsDelivr)
python check.py "$PWD"          # renders it in headless Chromium: every diagram must parse; prints node and edge counts
```

`check.py` needs `playwright` and a Chromium (`/usr/bin/chromium`).

## Keeping it true to the code

`graph.py` scans a checkout and prints the real import edges between top-level packages (module-level imports only, `TYPE_CHECKING` excluded). Run it from the `packages/` directory of a checkout: `python3 -I graph.py core` or `python3 -I graph.py gw`. A diagram edge is drawn from that output plus the lazy (function-local) imports read by hand; dashed edges are lazy.

Update rule: after each merged change that moves a dependency (a layering or boundary PR), edit the `.mmd` of the diagram it affects, rebuild, run `check.py`, and commit with the PR number in the message.

What is verified and what is inferred is stated in the note above each diagram in `architecture.html`.
